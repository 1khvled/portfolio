03 / How I work

Three disciplines, one developer.

Research, interface, code and deployment — handled in one place, without a handoff in the middle.

01

Interfaces

Product UI, design systems, responsive layout, accessibility and the states behind the screen: empty, loading, error, success.

  • Design systems with real constraints
  • Responsive layouts down to 320px
  • Keyboard and screen-reader paths
02

Data

Data modelling, API integration, static generation, scraping pipelines and charting. Where the number came from matters as much as how it looks.

  • Postgres and Supabase data models
  • Build-time data validation
  • Scrapers that fail loudly, not silently
03

Delivery

SEO, image pipelines, performance budgets and deployment. Shipping is the last 20% that decides whether a product feels finished.

  • Core Web Vitals budgets
  • Image and font pipelines
  • Preview deploys and clean rollbacks

04 / About

Solo by design,
end to end
by necessity.

I'm Khaled, a product engineer in Algiers. I started publishing code in 2024 and have spent the time since building products for markets I know first-hand.

I work alone, from the first sketch to the deploy. That means I can't hide behind a handoff: the data has to reconcile, the checkout has to work, and the page has to load on a phone with two bars of signal.

Most of my products are built for Algeria, which is its own design constraint — French, Arabic and English in the same interface; cash on delivery; prices that move every day; and users who will forgive a plain screen but never a wrong number.

“A good product is mostly the unglamorous parts done properly.”
01

Correct before clever. A simple model that reconciles beats a clever one that doesn't.

02

Static where possible. Fewer moving parts, faster pages, lower bills.

03

No dark patterns. No fake urgency, no hidden fees, no retention traps.
